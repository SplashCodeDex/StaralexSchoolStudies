# BECE / Mock / Exam Lesson Pattern Rules
## Non-mathematical subjects (Computing / ICT, CDT / CAD / Creative Arts and Design)

**Scope:** every grade and every subject that is **not** Mathematics (JHS 1–3 / B7–B9).  
**Source of truth:** the tagged question bank `BECE_MOCK_PAPERS` (587 Computing_ICT + 667 CDT_CAD questions, plus marking schemes) and the official NaCCA Common Core Programme PDFs.

Subject folders keep their own short `Rules.md` that **links here** and adds only subject-specific notes. Do not duplicate this file.

---

## 1. What a lesson is

A lesson is **Theory Questions and Answers**.

```
Q1.  What is a computer?
Ans. A computer is a machine that takes data in, processes it, and gives results out.
```

This is how the BECE theory papers actually ask and mark, and it is how the lesson is taught.

### 1.1 One answer per question

- A question demands **one** answer. That answer is **one sentence**.
- If the question asks for a list, it **says so** (`Mention five…`, `State three…`, `List four…`) and the answer is a **bulleted list**.
- Never bundle several different questions into one. Split them.

**Wrong**
> Q. What is hardware and name two input devices and explain why we need storage?

**Right**
> Q1. What is hardware?  
> Ans. Hardware is any physical part of a computer you can touch.  
> Q2. Mention two input devices.  
> Ans.  
> - Keyboard  
> - Mouse

### 1.2 Plain simple English

- Unpack every technical word **before** using it (a short "Words to know first" block).
- One idea per sentence. No clever phrasing. British English throughout (*organise*, *colour*, *programme*, *centre*).

### 1.3 Preambles are mandatory

Never open a lesson on the first technical question. Start with a short **preamble** that gives the big picture in everyday language, and a small diagram or map if the topic is spatial.

### 1.4 Teaching patterns that must appear in the body

These are how BECE actually tests. Teach them explicitly before the drills.

| Pattern | How to teach it | Bank examples |
| :--- | :--- | :--- |
| **Definitions** | `Q. What is X? Ans. X is …` | *What is a seam?* |
| **Enumerated lists** | `Q. State three X. Ans.` bullets | *State two methods suitable for joining sheet metals permanently.* |
| **Contrast / comparison** | a two-column table + a one-sentence "the difference is…" | *Warm vs Cool Colours*; *Primary vs Secondary vs Tertiary Colours*; *Temporary vs Permanent Stitches/Joints*; *Ferrous vs Non-Ferrous Metals*; *Dry vs Moist Cooking Methods*; *Operation (Cutting / Measuring / Striking / Marking-out) vs Trade (Blockwork / Woodwork / Metalwork) tools* |
| **Procedural step-by-step** | numbered steps `1. 2. 3.` for practical tasks | steps to change desktop wallpaper; create/rename/move a folder; insert a table or drop cap; prepare a design brief; execute a drawing/modelling stage |
| **Acronyms & full meanings** | one dedicated table of every syllabus acronym in the topic | `CPU, RAM, ROM, BIOS, USB, HDMI, VGA, OCR, OMR, MICR, RFID, PIN, URL, HTTP, HTML, ISP, LAN, WAN, CAD, CAM, PPE, PVC` |
| **Formulas, shortcuts & codes** | a compact table, then use them in examples | spreadsheet formulas (`=SUM(B2:B6)`, `=AVERAGE(…)`, ranges `A1:D10`); keyboard shortcuts (`Ctrl+C/V/X/Z/S/P`); pencil grades (`HB, 2B, BB, 2H`); wire/safety colour codes |

### 1.5 Worked BECE/Mock exemplars before the exercises

Immediately before the exercise block, include **Worked Exam Exemplars** pulled from (or modelled on) authentic bank questions. Show the **exact question stem**, the **mark allocation** (`[2 marks]`), and the **model marking-scheme answer**. Two or three is enough — this teaches the exam voice before the learner meets it cold.

## 2. The BECE question pattern (what the drills must look like)

Exams come as **two papers**. Exercises inside a lesson copy that shape.

### 2.1 Paper 1 — Objective (multiple choice)

Real stems from the bank:

| Stem type | Real example from the bank |
| :--- | :--- |
| `What is…` | *What is a component of a computer system that stores data and programs for future use?* |
| `Which of the following…` | *Which of the following is a social media platform?* |
| `What is the…` | *What is the main purpose of a firewall?* |
| `Which of the following is…` | *Which of the following is an input device?* |
| `…are known as` | *Stitches which are removed from an article after serving their purpose are known as* |
| `…is used for` | *The snips is used for* |
| `The sketch shown above is a` | *The sketch shown above is a* |

Format when writing a Paper 1 drill question:

```
1.  Which of the following is an input device?
    A. Printer        B. Keyboard        C. Monitor        D. Speaker
Answer: B — A keyboard puts data into the computer.
```

Rules:
- Exactly **four** options A–D.
- Options are **parallel** (same part of speech, same length class).
- The wrong options are plausible distractors from the same topic, not jokes.
- The answer is the **letter + one short sentence of reason**.
- If the bank question has a diagram ("the sketch shown above"), the drill **must** carry the figure.

### 2.2 Paper 2 — Theory / structured

Real stems from the bank:

| Stem type | Real example from the bank |
| :--- | :--- |
| `What is…` | *What is a seam?* |
| `State two/three/four…` | *State two methods suitable for joining sheet metals permanently.* |
| `Give two/three examples…` | *Give two examples of portable computer devices.* |
| `List three…` | *List three items that can be manufactured from sheet metal.* |
| `Explain…` | *Explain the fo[urth generation]…* |
| `Describe…` | *Describe and give examples of…* |
| `Differentiate…` | *Differentiate between…* |
| `Make a freehand sketch of…` | *Make a freehand sketch of a cross-cut saw.* |
| `Sketch…` | *Sketch a lap joint used in sheet metalwork.* |
| `The diagram/figure below shows…` | *The diagram below shows different communication networks. Use them to answer…* |
| `Identify the name of…` | *Identify the name of the networks labelled A, B, C, D and E.* |
| `Write the full meaning of…` | *Write the full meaning of the following acronyms: OCR, RFID, PIN, OMR.* |
| `Supply the…` (table) | *Supply the disease, signs and symptoms of deficiency…* |

Format when writing a Paper 2 drill question:

```
5.  (a) What is a seam?  (2 marks)
    (b) State two methods suitable for joining sheet metals permanently.  (2 marks)
    (c) Make a freehand sketch of a cross-cut saw.  (3 marks)

Answers
    (a) A seam is a line of stitching that joins two or more pieces of fabric
        together permanently.  (2 marks — definition 1, "stitching/joining" 1)
    (b) • Soldering
        • Welding
        (1 mark each, any two = 2 marks)
    (c) Sketch shows a handle, a blade, and teeth on the cutting edge.
        (3 marks — handle 1, blade 1, teeth 1)
```

Rules:
- **Mark allocations in brackets** on every sub-question: `(1 mark)`, `(2 marks)`, `(3 marks)`…
- Answers give **marking points**, the way a real marking scheme does:
  - `1 mark each × any 3 = 3 marks`
  - `(2 marks — definition 1, example 1)`
- Sub-questions are lettered `(a) (b) (c)` and numbered within when needed `(i) (ii)`.
- **Scenario openings** (the *Agyekum an IT specialist…* style) are allowed in the **exercise block only**, and only when the real bank question uses one. Keep them short. The **lesson body stays pure Q&A**.

### 2.3 The 8 exercise sections must mirror the BECE/Mock blueprint

**40 questions = 8 sections × 5 questions**, followed by **complete worked answers / marking-scheme solutions** for all 40.

| Section | Paper | Focus | Question shape |
| :---: | :---: | :--- | :--- |
| **1** | Paper 1 | Core definitions & concept identification | 5 MCQs, options A–D |
| **2** | Paper 1 | Tool, device, component & material **functions** | 5 MCQs, options A–D |
| **3** | Paper 1 | Classification, **exceptions** (`NOT` / `EXCEPT`), shortcuts & specs | 5 MCQs, options A–D |
| **4** | Paper 2 | **Visual / diagram / UI / tool identification & sketching** | 5 multi-part questions referencing lesson figures or requiring labelled sketches |
| **5** | Paper 2 | Structured theory: definitions & enumerated lists `(a) (b)` | `State two…`, `Mention three…`, `List four…` with `[marks]` |
| **6** | Paper 2 | **Comparisons, differentiations & table completion** | `Differentiate between…`, `Copy and complete the table…` |
| **7** | Paper 2 | **Procedural steps, acronyms, formulas & safety precautions** | `Write the steps to…`, `Write the full meaning of…` |
| **8** | Paper 2 | **Real-world NaCCA case-study scenarios** + **spiral review** | short scenario opens + `[Review]` items from earlier sub-strands |

Rules that apply across the blocks:

- **Authentic bank first** for every section. Generated questions top up to 5 per section.
- **Spiral review:** 10–20% (4 to 8 of the 40) come from previously taught sub-strands and are tagged `[Review]`. Section 8 always carries some.
- **Mark allocations in brackets** on every Paper 2 sub-question: `(1 mark)`, `(2 marks)`, `(3 marks)`.
- Answers give **marking points**, the way a real marking scheme does:
  - `1 mark each × any 3 = 3 marks`
  - `(2 marks — definition 1, example 1)`
- Sub-questions are lettered `(a) (b) (c)` and numbered within when needed `(i) (ii)`.
- **Scenario openings** (the *Agyekum an IT specialist…* style) are allowed in the **exercise block only**, and only when the real bank question uses one. Keep them short. The **lesson body stays pure Q&A**.

### 2.4 Where each type lives

| Part of the lesson | Style |
| :--- | :--- |
| Preamble | everyday English + one small diagram if spatial |
| Words to know first | short definition list |
| Teaching body | pure Theory Q&A (`Q. … / Ans. …`) |
| Contrast / procedure / acronym blocks | tables and numbered steps (§1.4) |
| Figures | only where the concept needs a visual (see §4) |
| **Worked exam exemplars** | real stem + `[marks]` + model marking-scheme answer |
| Exercise 1–8 | the 8-section BECE blueprint (§2.3) |
| Answers / marking scheme | after each section, or one full section at the end |

## 3. Question sources and quota

1. **Bank first.** Pull every authentic question from `BECE_MOCK_PAPERS` that is tagged to this lesson's indicators (or that clearly tests this sub-strand). Use the bank's real wording. Do not "improve" an authentic stem.
2. **Then generate** to fill the quota, in the same voice and style as the bank.
3. **Default quota** (unless the user overrides): **8 sections × 5 questions = 40**, split across Paper 1 and Paper 2 blocks. The user rule "7–10 exercises × 5 questions" still applies.
4. **Every bank question under the strand/substrand goes in.** If there are more authentic questions than the quota, **expand the quota** — do not drop authentic ones.
5. **Spiral review:** 10–20% of generated questions come from previously taught strands/sub-strands.

Query the bank like this:

```powershell
.venv\Scripts\python.exe w:/StaralexSchoolStudies/BECE_MOCK_PAPERS/src/bece_cli.py query --indicator <code> --subject <Computing_ICT|CDT_CAD> --limit 40 --format markdown
```

Always pass `--subject`. Codes collide across subjects.

## 4. Diagrams and pictures — contextual only

> "You don't just drop in diagrams and images. It is contextual, it really needs to be needed."

**Do not** add a figure to fill space. **Do** add one when the concept cannot be taught properly without it.

### 4.1 Topics that genuinely need a figure

| Subject | Topics that need a figure |
| :--- | :--- |
| Computing | computer components & ports; input/output/storage device identification; workstation & posture; network topologies; labelled hardware in "identify the parts" questions |
| CAD / CDT | elements of design (dots/lines/shapes); colour wheel; shading on a form; joints & tools (lap joint, tenon, saws); orthographic/isometric sketches; design-process diagrams |
| Any | any question the bank phrases as *the figure below shows…*, *the sketch shown above is a…*, *labelled A, B, C, D* |

### 4.2 How to draw them

Produce **real image files** (300 DPI `.png` only — never `.jpg` masters) and insert them into the PDF and the Markdown via `![Descriptive Caption](diagrams/filename.png)`.

The authoring pipeline is the **TikZ `.tex` → `.png`** one proven in
[`BECE_MOCK_PAPERS/data/diagrams/math_redrawn/`](../BECE_MOCK_PAPERS/data/diagrams/math_redrawn)
(46 audited templates render via `pdflatex` + `pdftoppm`):

1. Write a `standalone` LaTeX source `\documentclass[tikz,border=6pt]{standalone}` in the lesson's `diagrams/` folder (or in `BECE_MOCK_PAPERS/data/diagrams/math_redrawn/` when it generalises to a canonical template).
2. Compile: `pdflatex -interaction=nonstopmode -output-directory=<tempdir> <tex>`; rasterise: `pdftoppm -png -r 300 -singlefile <pdf> <out>`; copy the PNG next to the `.tex`.
3. **Keep only `.tex` (master) + `.png` (render).** Delete every intermediate `.pdf` / `.aux` / `.log` immediately. `.svg` and `.jpg` diagram assets are prohibited, as is any retained figure PDF.

- **Do NOT use fragile ASCII/text art** (`┌──┐`, `( . . )`, `\ /`) for spheres, colour wheels, isometric blocks, tools, UI windows, or network diagrams. Simple text arrows are fine only for the smallest ideas (a one-line "in → process → out" map).
- **Precise / labelled figures** (isometric cube, network map, colour wheel, tool or joint with labelled parts, transformed grids): **TikZ is the only authoring path** — it keeps geometry honest, labels crisp, and Computer Modern fonts consistent with the BECE papers.
- **Last resort only:** for a rough, non-annotated illustrative sketch that TikZ would be overkill for, Pillow/reportlab may draw directly into `diagrams/` at ≥150 DPI — but any figure carrying labels, measurements, or geometric claims must be TikZ.
- If a genuine image-generation tool becomes available again, it may be used for photographic-style references, never for figures with text baked in.

### 4.3 Every figure must

- Have a **caption** under it (`Figure 1: A desktop computer system`).
- Be referenced in the question (`The figure below shows…`, `See Figure 2`).
- Use **one clean font**, thin strokes, no gradients, no shadows.
- Live in the lesson folder:

```
Lesson-01-<Name>/
|-- Lesson_01_<Name>.md
|-- Lesson_01_<Name>.pdf
|-- build_lesson_pdf.py        (if a local build script is needed)
`-- diagrams/
    |-- figure_01_<slug>.png
    `-- figure_02_<slug>.png
```

## 4b. PDF rendering — zero misrendered characters

This rule exists because bare Type-1 `Helvetica`/`Courier` (WinAnsiEncoding) turns `₵ → × ÷ ≤ ≥ ≠ • ✓ ■` into black boxes.

1. **Register Unicode TrueType fonts** before building any PDF — `Segoe UI`, `Segoe UI Bold`, `Segoe UI Italic`, and `Consolas` from `C:\Windows\Fonts\`. Never use bare `Helvetica`/`Courier`/`Times` for body text.
2. **Zero raw LaTeX commands** in the output (`\vec`, `\frac`, `\circ`, `\Rightarrow`, `\times`, `\mathbf`, `\;`, `\ge`, `\le`). If one appears, the build is wrong.
3. **Zero black-box glyphs (`■`)** in any generated PDF. If a symbol has no glyph in the registered font, draw the figure instead of shipping tofu.
4. Maths notation:
   - inline symbols may use Unicode (`× ÷ ≤ ≥ π ² √ − ⁰ ¹ ² ³`);
   - **fractions, indices, matrices, and multi-line working** go through **LaTeX** (`pdflatex`, MiKTeX) and are embedded as crisp images.
5. Verify a sample page before declaring a lesson done: rasterise the PDF and read it back.

## 6. Pacing and delivery

- Structure the learning curve over **2 months**, 1–2 sub-strands per day/two days depending on depth.
- **Never rush.** A long sub-strand continues the next day. Split across days and let the user say *continue* / *proceed*.
- Always give **preambles and pre-lessons** — do not assume the learner already knows the basics.
- Update the tracker status only after the lesson + exercises + answers are actually delivered.

---

## 7. Worked-answer quality bar

- Theory answers: **one sentence**, or a **bulleted list** when the question asked for a list.
- Marking points mirror a real marking scheme (`1 mark each`, `any two = 2 marks`, definition + example).
- Never invent an official option when the paper's options are wrong — give the correct content and say so.
- British spelling and terminology throughout.

---

## 8. Quick checklist before a lesson is "done"

- [ ] Preamble in everyday English
- [ ] "Words to know first" block
- [ ] Lesson body is pure Theory Q&A (one answer per question)
- [ ] Every technical word unpacked before use
- [ ] Contrast / comparison tables, procedural steps, acronym tables where the topic has them
- [ ] Worked BECE/Mock exemplars (real stem + marks + model answer) before the drills
- [ ] Figures only where the concept needs one, each captioned and referenced; no ASCII art for complex shapes
- [ ] PDF uses Unicode TrueType fonts; zero raw LaTeX; zero `■` black boxes
- [ ] Exercise 1–8 follow the BECE blueprint (3× Paper 1 MCQ, then visual, structured, comparison, procedure, case-study/review)
- [ ] Every authentic bank question for that strand/substrand is in the drills
- [ ] Generated questions top up to the quota, 10–20% spiral review tagged `[Review]`
- [ ] Full answers/marking points for every question
- [ ] Folder tree matches §5
- [ ] Tracker updated
